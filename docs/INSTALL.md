# Установка собранной прошивки на Keenetic KN-3013

Установка собственной сборки KeeneticOS с Xray и настройка схемы: российские домены и сети — напрямую через провайдера, остальной трафик — через VLESS + Reality.

Перед началом выполните [локальную сборку по README](../README.md) и прочитайте [состояние проверок](VALIDATION.md). Ни сборщик, ни эта инструкция не обновляют роутер автоматически.

**Статус:** основа экспериментальной конфигурации проверялась на одном KN-3013 EAEU. Каждый новый персональный образ требует собственной проверки. Это пользовательская инструкция, не официальный способ установки от Keenetic.

## Что потребуется

- Keenetic Speedster **KN-3013 EAEU**. Совместимость с другими моделями и аппаратными вариантами здесь не подтверждена.
- Собственный работающий сервер VLESS + Reality и параметры клиентского подключения.
- **Подготовленный именно для этой модели образ с Xray, вашим клиентским профилем и правилами маршрутизации.**
- Компьютер с Windows, кабель Ethernet и официальная утилита Keenetic Recovery для KN-3013.
- Резервные копии исходной прошивки и настроек роутера.

Для шагов ниже нужен собственный образ из папки `dist/`, созданный комплектом сборки. Успешный `verification.json` подтверждает автоматические проверки содержимого, но не испытание загрузки на вашем устройстве. Сверьте SHA-256 образа с `SHA256SUMS` перед переносом в Recovery.

## Проверенная конфигурация

| Параметр | Значение |
|---|---|
| Модель | Keenetic Speedster KN-3013 EAEU |
| Основа образа | KeeneticOS 5.1.8 / `5.01.C.8.0-2` |
| Xray | 26.11.9, MIPS little-endian, soft-float |
| Транспорт | VLESS + Reality, TCP/RAW |
| Локальный вход Xray | SOCKS5, `127.0.0.1:1080`, UDP включён |
| Подключение провайдера при проверке | PPPoE |
| Проверка маршрутов | Телефон по Wi-Fi: российский контроль видит IP провайдера, зарубежный — IP VPN-сервера |

В проверенном образе отключены IntelliQoS/NTCE и дополнительные языки интерфейса, кроме русского и английского. Эти версии описывают проверенную установку, а не обещают совместимость с любыми последующими обновлениями.

## Как устроено подключение

```text
Телефон / компьютер → домашняя сеть Keenetic
                   → отдельная политика → локальный SOCKS5 → Xray
                                                           ├─ российские домены/IP → провайдер
                                                           └─ остальное → VLESS + Reality → VPS
```

Основное подключение самого роутера остаётся через провайдера. Правила разделения трафика находятся в конфигурации Xray. Название политики в веб-интерфейсе служит для выбора этой схемы устройствами.

### Требования к подготовленному образу

Проверенная сборка подготовлена на базе [Keenetic SDK](https://github.com/keenetic/keenetic-sdk/tree/5c74fc4d907383c91e8d6af3f5d67501f7acb171). В неё включены Xray, клиентская конфигурация, локальный SOCKS5 и служба автозапуска. Наличие компонента OPKG само по себе не означает, что Xray или Entware уже установлены.

В образ заранее должны входить штатные компоненты прокси-клиента, DNS-over-HTTPS и нужного подключения провайдера — в проверенной схеме PPPoE. Иначе необходимых пунктов интерфейса может не быть. Доустановка компонентов через обычное обновление KeeneticOS может заменить собственную сборку.

В этой реализации служба ждёт корректной даты перед запуском Xray: при холодном включении с датой 1970 года проверенная версия Xray могла аварийно завершаться. Доступ к DNS и синхронизации времени должен работать до запуска VPN.

До прошивки требуется проверить идентификатор модели, размер образа, контрольные суммы, конфигурацию Xray и работу службы запуска. Нельзя менять разметку флеш-памяти или подставлять образ другой модели. Успешный тест отдельных программ в эмуляторе не заменяет проверку загрузки на устройстве.

Персональный образ содержит клиентские данные VLESS. Его нужно хранить вместе с конфигурациями вне публичного репозитория. Для отдельного роутера удобно создать отдельного клиента на своём сервере; возможность использовать общий клиент одновременно зависит от серверных ограничений.

## Установка по шагам

### 1. Сохранить резервные копии

Открыть `http://192.168.1.1` → **Настройки системы → Файлы**. Скачать `firmware` и `startup-config`. Хранить их локально: настройки могут содержать данные доступа к интернету, Wi-Fi и администрированию.

### 2. Подготовить Recovery

Получить утилиту из [официального раздела восстановления KN-3013](https://support.keenetic.com/speedster/kn-3013/en/21740-os-recovery.html). В проверенной локальной папке установки использовалась структура:

```text
recovery/
├── krutil_en.exe
├── fw.ini
└── fw/
    └── KN-3013_recovery.bin
```

Скопировать полученный `KN-3013_5.1.8_Xray-26.11.9_PERSONAL.bin` в `fw/` под именем `KN-3013_recovery.bin`, заменив образ в этой отдельной папке Recovery. Перед запуском сверить его SHA-256 с исходным результатом сборки. Не переносить эту папку с персональным образом в GitHub. Исходную прошивку для восстановления хранить отдельно.

Запустить утилиту и подтвердить запрос прав Windows. Наш SDK-образ устанавливался через Recovery; штатный веб-загрузчик его отклонял из-за отсутствия фирменных метаданных/подписи.

### 3. Перевести роутер в режим восстановления

1. Отключить питание роутера и дождаться, пока погаснут индикаторы.
2. Отсоединить остальные сетевые кабели. Оставить подключение **компьютер → LAN-порт Keenetic**; синий WAN-порт временно свободен.
3. На обесточенном KN-3013 зажать **кнопку Wi-Fi** и, удерживая её, подключить питание.
4. Когда начнёт мигать крайний левый индикатор статуса, отпустить кнопку.
5. Дождаться сообщения об успешном восстановлении. Во время передачи и записи питание не отключать.
6. Закрыть Recovery кнопкой **Exit** и дождаться загрузки роутера.

На этой модели кнопка Wi-Fi выполняет функцию сброса; важно удерживать её именно при включении питания. [Кнопка Wi-Fi у KN-3013](https://support.keenetic.com/speedster/kn-3013/en/52020-resetting-the-system-settings-and-admin-password--wi-fi-button-.html).

### 4. Восстановить интернет

Вернуть кабель провайдера в синий порт. Открыть веб-интерфейс. Если настройки сбросились, восстановить свою резервную копию либо заново настроить подключение провайдера и Wi-Fi.

Дождаться подключения к интернету и правильной даты на роутере. В **Настройках системы → KeeneticOS и обновления** отключить автообновления. После восстановления старой конфигурации проверить этот переключатель повторно.

### 5. Создать локальное прокси-подключение

**Интернет → Другие подключения → Прокси-подключения → Добавить подключение**. Если оно уже восстановлено из резервной копии, проверить существующее.

| Поле | Значение |
|---|---|
| Имя | `Xray VPN` |
| Тип | **SOCKS v5** |
| Адрес | `127.0.0.1:1080` |
| Аутентификация | **Не использовать** |
| Использовать для выхода в интернет | **Включено** |
| Дополнительно → Подключаться через | Подключение провайдера; в проверенной схеме — PPPoE |

Сохранить и включить подключение. Адрес `127.0.0.1` относится к Xray внутри самого роутера. Клиентский профиль VLESS уже должен быть в образе.

### 6. Включить UDP

Открыть `http://192.168.1.1/webcli/parse`. В проверенной установке прокси назывался `Proxy0`. Убедиться, что это имя нужного интерфейса; при другом имени заменить его в команде.

Отправить команды по одной:

```text
interface Proxy0 proxy socks5-udp
```

```text
system configuration save
```

UDP также должен быть включён в SOCKS-входе Xray. [Команда SOCKS5 UDP в KeeneticOS](https://support.keenetic.com/speedster/kn-3012/en/35375-keeneticos-4-1.html).

### 7. Настроить DNS

**Интернет-фильтры → Настройка DNS → Системный → Добавить сервер**:

| Поле | Значение |
|---|---|
| Тип | **DNS-over-HTTPS** |
| URL | `https://cloudflare-dns.com/dns-query` |
| Интерфейс | **Любой интерфейс** |
| Домен / SPKI | Оставить пустыми |

Сохранить. DNS, привязанный исключительно к соединению провайдера, может быть недоступен отдельной политике, в которую включён только прокси. Keenetic рекомендует DoH/DoT для прокси-подключений. [Документация прокси-клиента](https://support.keenetic.com/speedster/kn-3013/en/49443-proxy-client.html).

### 8. Настроить политику домашней сети

В **Интернет → Приоритеты подключений**:

1. В **политике по умолчанию** оставить подключение провайдера **выше Xray VPN**. В этой схеме Xray работает на самом роутере, поэтому его внешние соединения должны выходить через провайдера.
2. Создать отдельную политику **«Россия напрямую, остальное VPN»** для сборки `ru-direct` либо **«Xray VPN»** для `all-vpn`. Название не задаёт правила маршрутизации: они уже встроены в профиль Xray.
3. Отметить в ней **только Xray VPN**. Автоматическое добавление новых подключений оставить выключенным.
4. Сохранить. На вкладке **Применение политик** перетащить сегмент **Основной** на новую политику.
5. У зарегистрированных устройств проверить значение **«Политика по умолчанию сегмента»**: индивидуальная политика устройства может перекрывать настройку сегмента.

Гостевые и другие сегменты назначаются отдельно, если VPN нужен и в них. [Политики подключений Keenetic](https://support.keenetic.com/speedster/kn-3013/en/17892-connection-policies.html).

### 9. Проверить на телефоне

Подключить телефон к Wi-Fi Keenetic. На время проверки выключить мобильный интернет и отдельное VPN-приложение на телефоне.

| Проверка | Ожидаемый результат |
|---|---|
| [Яндекс Интернетометр](https://yandex.ru/internet/) → IPv4 | Внешний IP вашего провайдера |
| [Cloudflare trace](https://1.1.1.1/cdn-cgi/trace) → строка `ip=` | Внешний IP вашего VPN-сервера |

Таблица относится к `ru-direct`. Для `all-vpn` оба контрольных сайта должны показывать адрес VPN-сервера.

Открыть нужные приложения. Затем сохранить настройки и проверить запуск VPN после выключения и повторного включения питания, дождавшись синхронизации времени. Это проверяет запуск с обесточенного состояния, когда часы роутера могли сброситься.

Для контроля российского направления не полагаться на `2ip.ru`: при проверке он перенаправлял на `2ip.io/ru/`, поэтому итоговая страница шла через VPN. Учитывать конечный домен после перенаправления.

### 10. Сохранить итоговую конфигурацию

Снова скачать `startup-config` и хранить его вместе с исходной прошивкой, собственным образом и его контрольной суммой вне GitHub.

## Ограничения и обслуживание

- Российские исключения основаны на `.ru`, `.рф` и списках российских IP. Это не безошибочное определение страны или принадлежности любого сайта. Дополнительные доменные исключения задаются в Xray при подготовке образа.
- В проверенной сборке списки встроены в образ. Для их обновления и смены клиентского профиля требуется подготовить новый образ.
- Обычное обновление KeeneticOS или изменение набора компонентов может заменить собственную сборку и удалить встроенный Xray. Обновления нужно готовить и проверять отдельно; отключённое автообновление не заменяет план обновлений безопасности.
- UDP был включён; отдельное измерение его внешнего IP на телефоне не выполнялось. Работа IPv6 через VPN и поведение при отказе WAN отдельно не подтверждены. При проверке публичного IPv6-маршрута по умолчанию не было.
- В публичные Issues и файлы не следует добавлять `vless://`-ссылки, UUID клиента, пароли, адрес панели управления, конфигурации, резервные копии или персональные образы. Для диагностики использовать обезличенные сведения.
